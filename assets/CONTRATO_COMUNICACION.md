# Contrato de comunicación A2A ↔ MCP Server ## Flujo 1. El agente A2A arma un mensaje siguiendo `a2a_task_message_schema.json`. 2. Lo envía al MCP Server con el API key en el header `X-API-Key`. 3. El MCP Server valida el API key. Si es inválido, responde `status: error` con `error_message`. 4. Si es válido, ejecuta la `action` pedida y responde con el mismo `task_id`, `status: success` y el resultado en `payload`. ## Autenticación - Mecanismo: API key en el header `X-API-Key`. - Origen de la key: [cómo se genera/entrega la key — pregúntalo mañana si no lo sabes aún] - Validación: [quién la revisa — probablemente el MCP Server, confirmar con Equipo A] ## Archivos de referencia - Agent card: `a2a_agent_card_ejemplo.json` - Esquema del agent card: `a2a_message_schema.json` - Esquema del mensaje: `a2a_task_message_schema.json` - Ejemplo de petición: `a2a_task_message_sample.json` - Ejemplo de respuesta: `a2a_task_message_response_sample.json`
